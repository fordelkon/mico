# Agent Context Review

Reassess context when a model or client upgrade changes its defaults, or when instructions become costly to load. Separate source-character counts from tokens and observed client injection.

## Approval boundary

Inspection is read-only. Present a source/line/cost/loading-scope list with repair, delete, move, rewrite, or keep; moves name a reachable destination. Explain the expected behavior change. Obtain approval before changing sources or creating recovery artifacts unless those artifacts are already authorized.

Preserve preferences, rejected approaches and reasons, machine facts, silent traps, normal behavior that resembles errors, no-write/no-upload clauses, irreversible-operation rules, and dated decisions. Keep permission gates verbatim. Keep commit, publication, reply, and deletion constraints reachable from the root. Do not remove project duplicates until every relevant client is proven to load their replacement.

## Evidence and migration

Inventory root instructions, ancestor and global rules, unscoped rules, skill and agent descriptions, conditional rules, and on-demand bodies separately. Deduplicate symlink targets. Installed, configured enabled, listed, invoked, and successfully read are different observations; no observed use is not proof of no use. Use structured tool calls and outcomes, not name searches, to establish use. Record the history cutoff and missing coverage without exporting unrelated transcripts or secrets.

After approval, retain exact private originals and a path/line/text/action/destination ledger with the confirmed IDs. Move conditional fragments verbatim and record that checkpoint before compressing entrypoints. Deterministic inventory, link and glob checks, and removed-line accounting belong in scripts. Judgment and optional modes belong in skills and references. A description states capability, trigger, and exclusions; `when_to_use` is not assumed to save context or work across clients.

Every removed nonblank line must map to an approved disposition. Check relative links, old filenames, real path-glob matches, and before/after costs. A ledger proves accounting, not semantic equivalence. Versioned plugin customizations need retained original hashes and patches; do not apply an old patch blindly to a different plugin version or treat cache edits as update-proof.

## Independent checks

Give a fresh reviewer only the disappeared lines and relevant repository/source roots, without the migration conclusions. Ask for searches by nouns and concepts. Restore original material constraints whose meaning has no reachable home; retain uncertain cases for a separate decision.

For actual loading, place a temporary unpredictable marker in a moved document. Use one fresh session for a matching real file and a second independent fresh session for a nonmatching file. Prompts do not contain the marker value or document name. Restrict reads to the intended target and inspect tool traces. Test a replacement root entry before removing compatibility. Remove markers afterward. Run each client independently and report unavailable probes as gaps; a subprocess hook test does not prove the host injected its output.

Apply [project verification](agent-guide.md#verification). Keep a private manifest of OS/client/model versions, audit cutoff, commands and outcomes, history gaps, approval IDs, snapshots, ledger, blind review, and loading results. Keep recovery data outside the shipped project.

## Writing anchors

Use **tight** for a fast, stable, low-overhead loop, with its observable signal. Avoid reportese: state the result and evidence.

| NO | OK |
| --- | --- |
| Completed comprehensive validation successfully. | `pnpm typecheck` passed; the Desktop loading probe is unavailable. |
| Ensure a fast, deterministic, low-overhead loop. | Use a tight loop: one command reproduces the symptom with a stable verdict. |
